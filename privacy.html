Privacy policy

Effective 14 October 2026 · Applies to the J.A.R.V.I.S. personal application

This policy explains exactly how JARVIS accesses, uses, stores and shares information from a Google account. It describes the application as it is actually built. Where JARVIS sends information outside the Mac it runs on, this policy says so plainly.

01What JARVIS is

JARVIS (“Just A Rather Very Intelligent System”) is a personal AI assistant developed privately by one person and run on that person’s own Mac for their own use. It is not a commercial product, it is not offered to the public, and there is no way for anyone else to create an account or sign in. In this policy, “the developer” and “the user” are the same person.

JARVIS consists of an interface that runs in a web browser on the Mac and a small backend program on the same Mac. The backend accepts connections from that Mac only. There is no JARVIS server on the internet; this website is a static information page and collects nothing.

JARVIS has not been verified or reviewed by Google. During Google sign-in you will see Google’s “unverified app” notice.

02Google account information accessed

When the user connects a Google account, JARVIS requests these three read-only permissions (“scopes”) and no others:

PermissionWhat it allows
calendar.events.readonlyRead events on calendars the account can access.
calendar.calendarlist.readonlyRead the list of calendars (names, and whether they are hidden or shown), so all of the user’s calendars can be included.
gmail.readonlyRead email messages, threads and labels, and the account’s email address.

JARVIS does not request permission to send email, change or delete email, manage labels, or create, change or delete calendar events, and its code contains no way to do any of these. It does not request access to Google Drive, Contacts, Photos or any other Google service, and it does not request the user’s name or profile picture.

03Calendar information retrieved

Only when the user asks a calendar question (for example “What’s on tomorrow?” or “Am I free on Friday?”), JARVIS asks Google for the user’s visible calendars and their events in the period asked about. Google returns full event records; JARVIS keeps only these details, in memory, while preparing the reply:

  • the names of the user’s visible calendars;
  • for each event: title, start and end times, whether it is all-day, location, a shortened description (up to 400 characters), whether it is tentative or shown as free, whether it repeats, the organiser’s name or address, the number of attendees, whether the user declined it, and whether it has a video-call link.

Section 9 explains which of these details are sent to the AI.

Cancelled events are ignored. Times are handled in the Europe/London time zone. JARVIS also works out free time from these events; that calculation happens on the Mac.

04Gmail information retrieved

Only when the user asks an email question (for example “Check my Gmail” or “Find the latest email from BMW”), JARVIS retrieves:

  • For lists and searches: each matching message’s sender, subject, date, Gmail labels (such as unread or important) and Gmail’s short preview text. At most 15 messages per question; usually 10 or fewer.
  • Full message text: only for messages the user specifically asks to read or summarise (at most three per question), and only while “Share email bodies with the AI” is switched on. The text is cleaned (formatting and hidden characters removed) and shortened to about 4,000 characters per message. When a message is read in full, Google also returns its recipients; JARVIS includes the “To” line with the message.
  • The account’s email address, read once when connecting, so the Settings screen can show which account is connected.

Attachments are not downloaded. Emails and calendar events often contain information about other people (senders, recipients, attendees); this is handled in the same way as described here.

05Why this information is accessed

Solely to answer the user’s own questions about their calendar and email inside JARVIS: listing appointments, finding free time, finding, reading and summarising emails, and pointing out messages that may need attention. The “may need attention” label comes from simple rules (unread, marked important by Gmail, from a person rather than an automated sender, or mentioning a deadline or payment), not from profiling.

Google information is never used for advertising, never sold, never used to assess creditworthiness, and never used to build profiles or train AI models.

06How Google sign-in works

JARVIS uses Google’s standard OAuth 2.0 sign-in for desktop applications. The user starts the connection in JARVIS’s Settings; the browser opens Google’s own sign-in and consent page, where the user chooses the account and the permissions to grant. JARVIS never sees or stores the Google password.

Google then returns a one-time code to the JARVIS backend on the same Mac (http://127.0.0.1). The connection is protected with PKCE and a single-use state value that expires after ten minutes, so a sign-in that JARVIS did not start is rejected. The code is exchanged with Google for an access token (valid for about an hour) and a refresh token, which JARVIS uses to renew access without asking the user to sign in again.

07How OAuth credentials are stored

  • The access token, refresh token, granted permissions and the connected email address are stored in one file on the Mac, encrypted with AES-256-GCM.
  • The encryption key is held in the user’s macOS Keychain, not alongside the file, so a copy or backup of the file alone cannot be read.
  • The file and its folder are readable by the Mac’s user account only.
  • Tokens are never shown in the JARVIS interface, never written to logs, never placed in conversation history and never sent to the AI.
  • The Google client ID and client secret for the application are kept in a local configuration file on the Mac that is excluded from source control.

This is encryption of stored credentials on the Mac. It is not end-to-end encryption, and JARVIS makes no such claim.

08What is stored on the Mac

  • Calendar events and email messages fetched from Google are not saved by JARVIS. They are held in memory only while a reply is being prepared and are not written to the conversation history or memory database.
  • JARVIS’s replies are saved. Conversation history (the user’s messages and JARVIS’s replies) is stored in a local database on the Mac. A reply that summarises calendar events or emails therefore contains that summary, and it is kept with the rest of the conversation.
  • A short note is saved with such a reply, for example “Checked Gmail · 3 messages · 1 read in full”. It records that a check happened, not the content.
  • Long-term memories are created only when the user explicitly asks JARVIS to remember something, or approves a suggestion drawn from the user’s own words. Nothing is remembered automatically from emails or calendar events.
  • The time of the last successful calendar and email check is kept in memory only and is lost when JARVIS restarts. The “share email bodies” setting is stored in a small settings file.

09When information is shared with OpenAI (Codex)

Calendar and email information does leave the Mac when the user asks about it. JARVIS writes its replies using an AI service. Currently that is OpenAI’s Codex, used through the developer’s own ChatGPT subscription. To answer a calendar or email question, JARVIS sends the AI the user’s message together with the details it retrieved for that question:

  • for calendar questions: the names of the calendars checked and, for each event in the period asked about, its date, time, title, calendar name, location, and short notes (tentative, shown as free, repeating, video call). Descriptions, organisers and attendee counts are not sent;
  • for email questions: each matching message’s Gmail identifier, sender, subject, date, Gmail’s preview text, whether it is unread, and any “may need attention” notes; plus, if email-body sharing is on, the sender, recipients, subject, date and cleaned text of specifically requested messages.

This information is sent only to produce the reply the user asked for. It is marked as reference data, and the AI is instructed never to follow instructions found inside emails or events. The AI cannot access the Google account itself; it has no tools and never receives a Google token.

Once sent, the information is processed by OpenAI under OpenAI’s own terms and privacy policy and the data settings of the developer’s ChatGPT account. JARVIS cannot control what OpenAI does with it. JARVIS’s local copy of Codex is configured not to keep its own conversation transcripts on the Mac.

JARVIS can technically be configured to use a different AI service instead (OpenAI’s API or Anthropic’s API, both paid and not currently set up). If one were selected, the same information would be sent to that provider instead, under its terms.

Google information is not shared with anyone else: no advertisers, data brokers, analytics services or other third parties.

10Turning off email-body sharing

In JARVIS, open Settings → Google and switch off Share email bodies with the AI. From then on, no message text is fetched or sent; email answers use only sender, subject, date, unread status and Gmail’s short preview. The setting takes effect immediately.

11Disconnecting Google

In JARVIS, open Settings → Google and choose Disconnect. JARVIS asks Google to revoke its access and deletes the encrypted token file from the Mac. If Google cannot be reached at that moment, the local tokens are still deleted and JARVIS says so; access can then be removed at Google directly at myaccount.google.com/connections. Removing access there also stops JARVIS immediately; it then asks to reconnect.

12Deleting stored information

Because JARVIS runs only on the user’s own Mac, the user can delete everything directly:

  • Google credentials: deleted by Disconnect (section 11).
  • Conversations (including replies that summarised calendar or email information): each conversation can be deleted in JARVIS’s conversation history. Deletion takes effect in the live database at once.
  • Memories: can be deleted individually or all at once in JARVIS’s Memory screen.
  • Backups: JARVIS keeps up to seven daily backups of its database on the Mac (and an extra copy before any database upgrade). A deleted conversation can remain in these local backups until they are replaced, normally within seven days, or until the backup files are deleted.

As JARVIS is used only by its developer, there is no remote copy for anyone to request deletion of. Questions about this policy can be sent using the contact details below. Information already sent to OpenAI is governed by OpenAI’s policies and can be managed through the ChatGPT account’s data controls.

14How information is protected

  • The backend listens on the Mac only and rejects requests addressed to other machines or sent from other websites.
  • Read-only Google permissions only; no code exists to send email or change calendars.
  • Encrypted token storage with the key in the macOS Keychain (section 7).
  • Email and event text is cleaned, length-limited and clearly fenced off as untrusted data before the AI sees it, to resist instructions hidden in emails.
  • The AI runs with all tools disabled, so it cannot act on anything it reads.
  • Request logs record only the type and address of each request, never message content, email content or tokens.

No system is perfectly secure, and JARVIS has not been independently audited or certified.

15Google API Services User Data Policy

[[CONFIRM BEFORE PUBLISHING: this statement is accurate only if model training is switched off in the ChatGPT account used by JARVIS (ChatGPT → Settings → Data controls → “Improve the model for everyone” = Off). Remove this line once confirmed.]]

JARVIS’s use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements. In particular:

  • Google user data is used only to provide the user-facing calendar and email features described in this policy, which are visible in JARVIS’s interface.
  • It is transferred only to the AI service described in section 9, only to produce the reply the user asked for, and only when the user asks.
  • It is not used for advertising, not sold, not transferred to data brokers or information resellers, and not used to determine creditworthiness or for lending purposes.
  • JARVIS does not use Google user data to develop, improve or train generalised AI or machine-learning models, and the ChatGPT account it uses has model training switched off.
  • No one other than the user reads the data. The developer, who is the user, sees it only as part of using JARVIS.

  • Changes: if the way JARVIS uses Google information changes, this policy will be updated before the change takes effect, with a new effective date, and the user will be asked to approve any new Google permission on Google’s consent screen.
